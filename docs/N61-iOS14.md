# iOS 14.8 on iPhone 6 (N61AP)

The test iPhone 6 booted iOS 14.8 (18H17), reached Setup Assistant, and
passed Apple activation. The successful test used the Mav10 modem
firmware and tickets from the same phone, the CommCenter compatibility
patch, and a boot bundle with the matching TrustCache. The phone
completed activation through Setup Assistant. Cellular calls and data
have not been verified.

Location services are disabled in this profile. On the test device,
locationd and the Wi-Fi service could wait on each other and prevent
SpringBoard from getting past the Apple logo. The patch updates both the
launchd service definition and its signed cache. The iOS 14 vibration
kernel patch is excluded from the tested configuration. Touch ID,
Bluetooth audio, microphone, and other hardware are pending validation.

## Inputs

Use macOS with full Xcode and its iPhoneOS SDK. Set up the host tools and
build an N61 iOS 12.5.8 SSH ramdisk with the test phone in DFU:

```sh
git submodule update --init --recursive
python3 -m pip install -r requirements.txt
python3 tools/setup.py
(cd tools/SSHRD_Script && ./sshrd.sh 12.5.8)
```

Keep native iPhone 6 iOS 12.5.8 (16H88) on the device as a firmware donor.
Place these Apple IPSWs in `ipsw/`:

- `iPhone_4.7_12.5.8_16H88_Restore.ipsw` (N61)
- `iPad_64bit_TouchID_14.8_18H17_Restore.ipsw` (J96 system and kernel)
- `iPhone_5.5_14.8_18H17_Restore.ipsw` (N66 drivers and services)
- `iPhone_4.7_14.8_18H17_Restore.ipsw` (N71 interface resources)

## Installation status

The code exposes the N61 profile through the following commands. The
dry run lists the stages and patches. A fresh end-to-end install from this
branch is still awaiting a hardware test. The successful activation
followed an incremental install and repair on one phone.

```sh
python3 n56patcher.py all --target n61-ios14 --dry-run
```

The installer writes APFS volumes and changes roles. Back up your data
before running any install. On our test phone, the iOS 12 files remained
readable, but iOS 12 returned to recovery when its original system and data
volumes no longer had their native APFS roles. Do not count on a normal
iOS 12 boot after installing.

The test phone used SystemB on slice 4 and a separate Data14 on slice 6.
These slice numbers are specific to that phone. The installation used a
fresh Data14 volume, and it only booted after the system keybag was
created. The experimental `--replace-ios13` path can erase the old
iOS 13 system and data volumes. That path was not used end to end for
the successful activation.

Use the same work directory and matching boot bundle for subsequent DFU
boots. Keep your IPSWs, tickets, device logs, and personalized firmware
local.

## Wallpapers and app icons

The N61 profile derives all 15 image-based adaptive still wallpapers
from the iOS 14.8 N71 IPSW as light and dark JPEGs. The catalogue is
verified on the test device. Displaying and applying these wallpapers
in Settings still needs a hardware test. This conversion covers still
image pairs, while procedural and Live wallpapers use other formats. Some installed Apple apps can
show white icons even with the iPhone resources staged on the system
volume. Repairing those existing app bundles is still under test.
