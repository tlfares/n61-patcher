# iOS 14.8 on iPhone 6 (N61AP)

The test iPhone 6 (N61AP / iPhone7,2) booted iOS 14.8 (18H17), reached Setup
Assistant, passed Apple activation, and reached the Home Screen. The successful
activation used the phone's own personalized modem firmware and tickets, the
CommCenter compatibility patch, and a matching TrustCache. Cellular calls and
mobile data have not been verified.

Location services are disabled in this profile. On the test device,
`locationd` and Wi-Fi could wait on each other and prevent SpringBoard from
getting past the Apple logo. The patch updates both the launchd service
definition and its signed cache. See the current device results below; the
port remains a work in progress.

## Inputs

Use macOS with full Xcode and its iPhoneOS SDK. Set up the host tools and
build an N61 iOS 12.5.8 SSH ramdisk with the test phone in DFU:

```sh
git submodule update --init --recursive
python3 -m pip install -r requirements.txt
python3 tools/setup.py
(cd tools/SSHRD_Script && ./sshrd.sh 12.5.8)
```

Keep native iPhone 6 iOS 12.5.8 (16H88) on the device as a firmware donor.
Place these Apple IPSWs in `ipsw/`:

- `iPhone_4.7_12.5.8_16H88_Restore.ipsw` (N61)
- `iPad_64bit_TouchID_14.8_18H17_Restore.ipsw` (J96 system and kernel)
- `iPhone_5.5_14.8_18H17_Restore.ipsw` (N66 drivers and services)
- `iPhone_4.7_14.8_18H17_Restore.ipsw` (N71 interface resources)

## Installation status

The code exposes the N61 profile through the following commands. The
dry run lists the stages and patches. A fresh end-to-end install from this
branch is still awaiting a hardware test. The successful activation
followed an incremental install and repair on one phone.

```sh
python3 n56patcher.py all --target n61-ios14 --dry-run
```

The installer writes APFS volumes and changes roles. Back up your data
before running any install. On our test phone, the iOS 12 files remained
readable, but iOS 12 returned to recovery when its original system and data
volumes no longer had their native APFS roles. Do not count on a normal
iOS 12 boot after installing.

The test phone used SystemB on slice 4 and a separate Data14 on slice 6.
These slice numbers are specific to that phone. The installation used a
fresh Data14 volume, and it only booted after the system keybag was
created. The experimental `--replace-ios13` path can erase the old
iOS 13 system and data volumes. That path was not used end to end for
the successful activation.

Use the same work directory and matching boot bundle for subsequent DFU
boots. Keep your IPSWs, tickets, device logs, and personalized firmware
local.

## Test status and limitations

Results below are from one iPhone 6. “Works” means the behavior was observed
on the device, not that it has been tested across multiple phones or clean
installations.

| Area | Result | Notes |
| --- | --- | --- |
| Boot and setup | Partially works | A tethered boot reached Setup Assistant and the Home Screen. A later, uncommitted patch set returned to Recovery; the current device is not in a confirmed working boot state. |
| Apple activation | Works | Activation completed on the test phone with its personalized assets. |
| Home Screen icons | Works in the tested state | Stock icons that were initially blank were repaired. |
| iOS 14 still wallpapers | Works in the tested state | Adaptive light/dark still wallpaper choices were confirmed. Live and procedural wallpapers are not covered by that result. |
| Vibration | Works | The motor was confirmed working. |
| Wi-Fi | Partially works | Wi-Fi connectivity works. Opening a network's password screen was slow and could temporarily freeze Settings. |
| Camera | Does not work | Both camera previews remained black; selecting slow motion crashed Camera. |
| Microphone | Does not work | Voice recording failed. Siri's text-entry mode worked, which does not validate the microphone. |
| Speaker output | Not verified for this iOS 14 build | Earlier speaker observations were not made on this configuration. |
| Phone and Weather apps | Do not work in the latest check | They appeared installed but did not open. |
| Battery percentage and brightness | Reported working | The user confirmed both recovered after earlier incorrect battery/brightness readings. Battery Health settings have not been verified. |
| Touch ID | Not verified on iOS 14 | Do not infer the iOS 13 result applies to this build. |
| Bluetooth audio, cellular calls/data, App Store, Apple Pay, Health, shutdown | Not verified or unresolved | No end-to-end result is available for this iOS 14 configuration. Shutdown has previously remained on a long spinner. |

### Unvalidated local changes

On 2026-11-16, additional local changes were applied to the test phone for
camera configuration, battery-health UI, and Phone/Weather app resources. The
following boot attempts returned to Recovery. These changes are intentionally
not included in the published branch or its install instructions until they
have been validated. The local working tree may contain these experimental
files; use the committed branch when reproducing the documented state.

The device-specific test layout used SystemB on APFS slice s4 and Data14 on
s6. The iOS 12 system volume s1 and old iOS 13 data volume s5 were not erased
during the latest patch attempt. These slice numbers are not universal.

## Wallpapers and app icons

The N61 profile derives all 15 image-based adaptive still wallpapers
from the iOS 14.8 N71 IPSW as light and dark JPEGs. The wallpaper choices
and corrected stock icons were confirmed on the test device. This conversion
covers still image pairs; procedural and Live wallpapers use other formats.
The separate local Phone/Weather resource changes remain unvalidated and are
not part of the published install path.
