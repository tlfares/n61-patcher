# iPhone 6 (N61AP) — experimental iOS 13.7 second system

[Upstream project](https://github.com/CelestialSayuki/n56-patcher) · [N61 profile](../targets/n61_ios13.py)

This fork adapts CelestialSayuki's **iPhone 6 Plus** second-system patcher to the **iPhone 6, non-Plus**. An N61 device has booted iOS 13.7, completed setup and downloaded apps from the App Store. This is an experimental port with missing hardware support, not an official iOS update or a daily-use release. The instructions below use the repository's CLI; no AI service is required.

## Device names matter

| Board | Device | Product identifier | Role here |
| --- | --- | --- | --- |
| **N61AP** | **iPhone 6** | **iPhone7,2** | The physical device targeted by this guide; A8 |
| N56AP | iPhone 6 Plus | iPhone7,1 | The original upstream target; A8 |
| N66AP | iPhone 6s Plus | iPhone8,2 | iOS 13 phone donor; A9, **not** the iPhone 6 Plus |
| N71AP | iPhone 6s | iPhone8,1 | Matching 2× iPhone UI resources |
| J96AP | iPad mini 4 | iPad5,1 | iOS 13 root filesystem and kernel donor |

Use `--target n61-ios13` in **every** patcher command. This fork defaults to `n61-ios13`, but explicit target selection makes saved commands unambiguous. The N61 profile leaves ECID and UDID empty: it checks the board rather than hardcoding the original test device.

## What currently works, and what does not

The status below describes the N61 experiment. Upstream N56 results must not be assumed to apply to N61.

| Area | N61 status |
| --- | --- |
| Boot, display, touchscreen, SpringBoard | Reached and used on the test device |
| Wi-Fi | Working on the test device |
| Setup / activation | Completed with the N61 telephony compatibility patch; this is not an Activation Lock bypass |
| App Store | Purchases list and cloud downloads worked after account authentication; app and account compatibility still depend on Apple's services |
| iPhone icons and Settings resources | N71 2× resources are selected; staged Apple app resources are included for fresh installs |
| checkra1n userland / Cydia | Installed; the Cydia icon was present on the test device |
| Touch ID | **Not working. Disabled in the default kernel build.** Enabling the sensor alone previously caused repeated SEP transport errors |
| Vibration | **Working on the tested N61 and enabled by default.** The native DRV2604 driver loads; the tester confirmed the motor works |
| Audio | **Speaker output confirmed working.** Dictaphone's record button currently does nothing; AirPods pair and connect but cannot be selected as the output. Microphone capture and Bluetooth audio routing are therefore not working on the tested device. The separate experimental `audio` transplant remains disabled |
| Health | The upstream `health` repair is excluded because rebuilt libraries did not match its pinned manifest; do not assume Health functionality |
| Wallpapers | Original HEIC catalog **disabled** after a freeze/loop. The N61 install derives four adaptive JPEG pairs locally; generation is checked, but the automatic install path still needs a fresh-device test |
| Bluetooth, cellular calls/data, GPS, cameras, sensors, battery life and long-term stability | Not comprehensively tested; inclusion of a patch is not confirmation that the feature works |

The iPhone 6 has a vibration motor, not the Taptic Engine introduced on later iPhones. This driver restores the existing vibration motor; it cannot add newer haptic hardware.

The second system uses a **tethered boot**: keep the matching Mac-side boot bundle. A normal restart does not automatically rerun this patched boot chain.

## Before installing

- Use an **iPhone 6 / iPhone7,2 / N61AP** whose installed SystemA is **iOS 12.5.8, build 16H88**. The source checks that build. Other builds and other devices are not covered by these instructions.
- Make a backup and retain any account credentials needed to activate your own device. Installation writes APFS metadata and clears the destination SystemB tree. A mistake or a restore can erase all device data.
- Start from the expected stock volume layout. This profile assumes existing iOS 12 volumes `s1`, `s2`, `s3`, then adds `s4` and `s5`. The APFS layout guard checks volume names, slices and superblock checksums before writes, and rejects unrelated existing layouts. Do not change volume numbers to force an unsupported layout.
- Use macOS with **full Xcode and its iPhoneOS SDK**, Git, Python 3 and a direct USB data connection. Command Line Tools alone do not supply the required iPhoneOS SDK. Open Xcode once to complete its setup.
- Allow enough Mac disk space for four IPSWs, their extracted root filesystems and build output. The device's iOS 13 base tree is roughly 9 GB before its DataB and additional apps; both systems share the APFS container. Small-capacity configurations need particular care and have not all been validated.
- This port disables normal code-signing enforcement and installs jailbreak tooling. Use an experiment device rather than relying on it for sensitive daily use.

## 1. Clone this fork and set up the tools

Clone this fork and keep the submodules at the revisions recorded by the repository.

```sh
git clone --recursive https://github.com/tlfares/n61-patcher.git
cd n61-patcher
mkdir -p ipsw build
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python tools/setup.py
```

`tools/setup.py` initializes the required submodules and builds or fetches the pinned tools and creates the local `donors/` inputs. It downloads checkra1n 0.12.4 userland and the pinned APFS helper inputs. Firmware and generated output are intentionally not committed.

Commands in this guide use `.venv/bin/python` explicitly so that root and non-root stages use the same Python installation. Run all commands from the repository root unless a command explicitly changes directory.

## 2. Supply the exact IPSWs

The included downloader retrieves the four exact IPSWs from Apple HTTPS CDN URLs and verifies each file's pinned size and SHA-256. The repository contains the download manifest, not Apple firmware.

```sh
# Inspect the pinned URLs and hashes without downloading.
.venv/bin/python tools/fetch_ipsw.py --list
# Download missing inputs and verify the local files.
.venv/bin/python tools/fetch_ipsw.py
# Verify existing local inputs without network access.
.venv/bin/python tools/fetch_ipsw.py --verify-only
```

The manifest is [tools/firmware_n61.json](../tools/firmware_n61.json). If supplying your own downloads, preserve these filenames and run the verification command:

```text
ipsw/iPhone_4.7_12.5.8_16H88_Restore.ipsw
ipsw/iPhone_5.5_13.7_17H35_Restore.ipsw
ipsw/iPhone_4.7_13.7_17H35_Restore.ipsw
ipsw/iPad_64bit_TouchID_13.7_17H35_Restore.ipsw
```

These correspond to N61, N66, N71 and J96 respectively. The `iPhone_5.5_13.7` file is the **6s Plus donor**, not firmware being restored directly to your iPhone 6. The first extraction is cached under `ipsw/cache/`; derived Wi-Fi inputs are isolated per native board to avoid reusing another target's firmware.

The patch offsets and compatibility checks target these exact builds. Do not substitute a different iOS 13 release or a similarly named IPSW.

## 3. Generate the SSH ramdisk

Connect the iPhone and enter DFU. Its screen should be completely black; a cable/computer recovery screen is not DFU. On an iPhone 6, hold Home and the side button together for about 8–10 seconds, then release the side button while continuing to hold Home until the host detects DFU. Repeat if the Apple logo appears.

Generate the ramdisk once:

```sh
(cd tools/SSHRD_Script && ./sshrd.sh 12.5.8)
```

This prepares `tools/SSHRD_Script/sshramdisk/`. Use the patcher's `ramdisk` stage below to boot it. Do **not** use the upstream ramdisk's generic `mount_filesystems` command for this layout: mounting the encrypted iOS 12 Data volume (`s2`) was observed to hang the APFS container.

## 4. Check the selected profile

These commands only print the selected patches or the proposed flow:

```sh
.venv/bin/python n56patcher.py list --target n61-ios13
.venv/bin/python n56patcher.py all --target n61-ios13 --workdir build/n61-current --dry-run
```

A dry run does not inspect the phone, validate its volume layout, produce boot images or prove an install will succeed. The real install applies the layout guard before filesystem writes. The guard and related regression checks pass 14 offline tests; a complete clean-device install of the newly packaged flow remains unvalidated. Verify that the default list excludes the unfinished N61 features described above.

## 5. Install and boot

With the device in DFU and all four IPSWs available, run:

```sh
sudo .venv/bin/python n56patcher.py all --target n61-ios13 --workdir build/n61-current
```

The flow decrypts the native iBSS/iBEC using the device, boots the SSH ramdisk, extracts this device's onboard IM4M, creates SystemB/DataB, writes the iOS 13 tree, applies overlays, sets APFS roles, builds five boot images and sends them.

The filesystem transfer is large and can take tens of minutes. Wait for its terminal output; the progress on the phone is not a reliable estimate. When the final boot stage says it is waiting for DFU, put the phone back in DFU while leaving the command running. Do not disconnect it during a filesystem write.

The profile expects this layout after installation:

| Slice | Purpose | Mount used by this patcher |
| --- | --- | --- |
| `disk0s1s1` | Native iOS 12 SystemA | `/mnt1`, read-only |
| `disk0s1s2` | Native encrypted iOS 12 Data | Not mounted by this flow |
| `disk0s1s3` | Baseband volume | Role adjusted by the finalization stage |
| `disk0s1s4` | iOS 13 SystemB | `/mnt6` |
| `disk0s1s5` | iOS 13 DataB | `/mnt7` |

DataB content protection is enabled by default. The native personalized iOS 12 SEP firmware is copied from SystemA; no SEP replacement or shared keybag from another device is needed. Do not use `--data-protection none` as a generic troubleshooting switch.

### If you need to run stages separately

The complete `all` flow is recommended for a fresh install because it decrypts native boot inputs **before** entering the ramdisk. If those inputs have already been generated, the equivalent stages are:

```sh
.venv/bin/python n56patcher.py ramdisk --target n61-ios13
.venv/bin/python n56patcher.py extract-im4m --target n61-ios13
.venv/bin/python n56patcher.py status --target n61-ios13
sudo .venv/bin/python n56patcher.py install --target n61-ios13 --workdir build/n61-current
sudo .venv/bin/python n56patcher.py build --target n61-ios13 --workdir build/n61-current
# Put the iPhone back in DFU before the next command.
.venv/bin/python n56patcher.py boot --target n61-ios13 --workdir build/n61-current
```

The staged build also uses `sudo` because the install stage may have created root-owned files in that same work directory. `install` includes `volumes`, `rootfs` and `patch-rootfs`. **It is a fresh SystemB install**, not a repair command: the `rootfs` stage clears the existing SystemB contents. Do not rerun `install`, `rootfs` or `all` merely to reboot an installed phone.

## 6. First boot

Complete setup on the phone with Wi-Fi and authenticate normally with your own account if required. This fork fixes the N61 radio-product mapping without spoofing the device identity. It does not skip activation, provide an activation record or remove Activation Lock.

If Cydia is still completing its first initialization, allow it approximately 30 seconds after boot; the bootstrap runs in the background. An App Store purchase requires the app to support iOS 13 and the account/server transaction to succeed. The test phone eventually displayed purchases and completed cloud downloads; this does not guarantee every old app remains available.

Do not manually copy the original HEIC catalog back onto this port; it caused repeated SpringBoard restarts. The N61 installer instead generates the JPEG workaround described below. Use a photo if the generated catalog is unavailable.

## Subsequent boots and updates

Keep the **entire** `build/n61-current/` directory privately on your Mac. It contains five paired images:

```text
boot_iBSS.img4
boot_iBEC.img4
boot_DT.img4
boot_TC.img4
boot_KC.img4
```

For another iOS 13 boot, enter DFU and reuse that exact bundle:

```sh
.venv/bin/python n56patcher.py boot --target n61-ios13 --workdir build/n61-current
```

After a stock restore, extract a new IM4M and rebuild. An old bundle can contain a stale ticket even when `state/IM4M.bin` exists. Never copy another person's IM4M or boot bundle.

For a kernel experiment, use a **new** work directory, retain the known-working one and build explicitly before booting. A newly generated TrustCache may also depend on rootfs changes, so do not treat arbitrary boot bundles and installed rootfs versions as interchangeable.

## Vibration and Touch ID status

The native N61 DRV2604 transplant passes static checks covering 1,244 decoded instructions, 50 virtual-call ABI adjustments and 205 added slide references. It was then booted on the test iPhone 6, the driver registered, and the tester confirmed that vibration works. The default N61 profile now includes `vibration`.

For an existing installation, build a new bundle in a separate work directory and boot it through DFU. No rootfs reinstall is needed for this kernel change:

```sh
.venv/bin/python n56patcher.py build --target n61-ios13 --workdir build/n61-vibration
.venv/bin/python n56patcher.py boot --target n61-ios13 --workdir build/n61-vibration
```

Keep your previous working bundle for recovery. These commands do not rerun `install` or clear SystemB.

Touch ID remains disabled. Restoring initialization attaches the biometric driver, but SEP transfers fail. A second experiment reproducing iOS 12's legacy reply-command acceptance rule still failed the transfer check and triggered repeated sensor recovery. That experiment is excluded from the default build; a complete legacy transport adaptation is still required. The vibration and biometric drivers are independent.

## Wallpapers

The original iOS 13 still-wallpaper catalog uses HEIC and was disabled after it froze this N61 port. A light/dark JPEG conversion worked on the test phone. The N61 profile now selects `wallpaper_format="jpeg-adaptive"`, and `rootfs.adaptive_wallpapers` generates Orange, Green, Blue and Black iOS 13 pairs from the local N71 rootfs during installation. Apple artwork stays local.

You can generate the same overlay offline from a read-only mounted N71 rootfs:

```sh
.venv/bin/python tools/n61_wallpapers.py \
  --source-root /path/to/mounted/N71/rootfs \
  --output build/n61-wallpapers
```

The helper uses macOS `sips` and writes the converted JPEG files and catalog metadata. It does not contact an AI service. All 16 generated JPEGs and their plist references were checked offline. The automatic fresh-install path has not yet been tested from a clean device; treat that as a validation gap rather than a promise of identical behavior on every install.

## Troubleshooting and recovery

| Symptom | Action |
| --- | --- |
| The host never sees DFU | Retry the button sequence; verify a data-capable USB cable. A recovery screen is a different mode |
| `SystemA build` mismatch | Use the required native 16H88 environment. Do not suppress the check or edit offsets to force another version |
| Missing IPSW / donor file | Verify filenames and rerun setup as needed. Leave Apple firmware out of Git |
| Install has stopped with an error | Save the terminal output and identify the failed stage. Do not blindly run `rootfs` or `all` again over a working installation |
| SSH returns `Permission denied` or `iproxy` cannot bind its port | Keep the device connected and do not boot the target. Check for another iPhone or a stale `iproxy` using the configured local port; stop only the conflicting proxy, then reconnect to the ramdisk and inspect the APFS layout before retrying a rootfs write |
| `Resource busy` after manually mounting native Data | Restart into DFU, boot the ramdisk again, and avoid mounting `s2` |
| Activation says a value is missing | Confirm the N61 target and its baseband overlay were used. Capture the exact error; do not prepare/restore with Configurator as an activation workaround |
| Touch ID setup fails | Known limitation. Restoring only the disabled sensor initialization is not a fix |
| A boot experiment loops | Re-enter DFU and send the last working bundle with the `boot` command |
| Wallpaper caused a SpringBoard loop | Rebooting with another kernel alone may retain the bad wallpaper preferences; retain a working photo configuration and report the exact catalog used |

Finder or Apple Configurator **Restore** can erase this experimental installation and return the device to Apple's restore path. Do not choose Restore if your goal is to preserve SystemB. This fork does not yet provide a validated one-command uninstall that safely removes only the added volumes.

## Reporting a problem

Include the commit, `--target` value, hardware model, native iOS build, failing stage, selected feature list and a short redacted terminal excerpt. Say whether the issue occurs with the default profile or an experimental kernel. Remove ECID, UDID, serial number, account information, activation records and other personal data before sharing a log. Never upload `state/`, keybags, IPSWs or device-personalized images.

## How the port was made

The port keeps the upstream J96 iOS 13 base, changes native extraction and DeviceTree/touch configuration to N61, maps the native `tempranillo` Wi-Fi blobs to the donor kernel's expected `barbera` names, copies native N61 model files, and adds N61's Mav10 entry to the telephony compatibility table. UI resources come from the N71 2× donor rather than the N66 3× donor. The complete dependency and patch selection is in the N61 target and the existing `patches/` registry.
